# dth30-fw

DTH30 シリーズ（DT-H30/U2、DT-H50/U2）のチップ ViXS XCode2 で動く、自作のファームウェア。
純正ドライバ `BufFsUSB.sys` に入っているファームウェアの代わりに使うことを目指している。純正のコードやデータは含まない。

**開発中。** Raw ストリーム（スクランブルされたままのフル TS）と、B-CAS カードで復号した Program ストリームが出る。
確認した機種は DT-H50/U2 だけで、カードの抜き差しと長時間の動作はまだ確かめていない。

## できること

| 項目 | 状態 |
|---|---|
| 起動、ホストとの握手、ハートビート | 動く |
| コマンド 0（ping）、27（OTP の署名。純正と同じ値になる） | 動く |
| コマンド 24（TS 入力の設定） | 動く |
| コマンド 8 種別 1 / 9 / 10（Raw ストリームを開く、閉じる、flush） | 動く |
| コマンド 25 / 26 / 11（CAS オブジェクト、カードのリセット） | 動く。カードの状態（挿入、活性化、INIT 完了）をエンドポイントへ報告する。抜き差しは未確認 |
| カード: リセット、ATR、T=1、INIT（システム鍵と CBC 初期値を鍵 RAM へ） | 動く |
| コマンド 8 種別 5 / 9 / 10（Program ストリーム） | 動く。ヌルを除いた全 TS で、指定されたサービスの ES は復号済み。ECM をカードへ送り、制御語を鍵 RAM に書く |

## ビルド

CPU は MIPS 4Km（MIPS32 リリース 1、リトルエンディアン、FPU なし）。Rust にこの CPU 向けの出来合いのターゲットは無いので、
`core` をソースからビルドする。`rust-src` コンポーネントが要る（`rust-toolchain.toml` に入れてある）。

**ふだんは自分でビルドしなくてよい。** `dth30-core` のビルドスクリプトがこのクレートをビルドし、できたイメージをプログラムに組み込む
（`Firmware::own`）。`dth` / `dth30-diag` は、`--firmware` を付けなければこの組み込みのファームウェアを使う。
`rust-src` の無い環境では、環境変数 `DTH30_NO_OWN_FIRMWARE=1` を付けてビルドすれば、ファームウェア抜きでビルドできる。

単体でビルドするには:

```sh
rustup component add rust-src
cd crates/dth30-fw
RUSTC_BOOTSTRAP=1 cargo build --release
```

`RUSTC_BOOTSTRAP=1` は、stable のツールチェーンで `-Z build-std` を使うためのもの。nightly を使うなら不要（`cargo +nightly build --release`）。
PowerShell では `$env:RUSTC_BOOTSTRAP = '1'` としてから `cargo build --release`。

できるのは ELF なので、生のイメージに直す。`rust-objcopy` はツールチェーンに入っている。

```sh
"$(rustc --print sysroot)/lib/rustlib/$(rustc -vV | sed -n 's/^host: //p')/bin/rust-objcopy" \
    -O binary target/mipsel-xcode2/release/dth30-fw dth30-fw.bin
```

## 使い方

何も指定しなければ組み込みのものが使われる。単体でビルドしたイメージは、`--firmware` に `BufFsUSB.sys` の代わりに渡す。
イメージの +0x100 に印（`DTH3`）があり、`dth30-core` はそれを見てハッシュの照合なしで読み込む。

```sh
dth30-diag fw dth30-fw.bin
dth30-diag bring-up --firmware dth30-fw.bin
dth30-diag record 27 --raw -o raw.ts --firmware dth30-fw.bin
```

## 作り

- コア 0 だけを使う。割り込みは使わず、ホストからの要求・DMA の完了・ストリームのリングを 1 つのループで見て回る。
- ホストやチップのハードウェアと共有するメモリは、すべて kseg1（キャッシュなし）で触る。自分のコードとデータは kseg0（キャッシュあり）。
- 例外はすべて致命エラーとして扱い、純正と同じ場所に記録を残す（FB 0x530 = 0xDEADC0DE、場所、sp、コア番号。FB 0x560 = 原因、EPC、Status、Cause、BadVAddr、ra）。

| ファイル | 内容 |
|---|---|
| `src/boot.rs` | イメージの先頭（ベクタ表）、リセットからの起動、例外の入口 |
| `src/hw.rs` | レジスタと SDRAM へのアクセス、時計 |
| `src/host.rs` | 握手、コマンド、メッセージ、ハートビート |
| `src/otp.rs` | コマンド 27 |
| `src/dma.rs` | DMA エンジン |
| `src/demux.rs` | デマルチプレクサ（PID フィルタ、チャネル、リングの読み手） |
| `src/ts.rs` | TS 入力の設定、全 PID のチャネル、Raw ストリーム |
| `src/program.rs` | Program ストリーム（ES のチャネルとデスクランブラ、ECM の取り出し、出力） |
| `src/card.rs` | B-CAS カード（検出、リセット、ATR、T=1、INIT） |
| `src/cas.rs` | CAS オブジェクト（カードの状態の報告、リセット要求） |
| `src/keyram.rs` | 鍵 RAM への書き込み |

### メモリの使い方（SDRAM の物理アドレス）

| 範囲 | 内容 |
|---|---|
| 0x000000〜0x00048F | 例外ベクタ（ホストが置き、起動後にファームウェアが置き直す） |
| 0x000010、0x000020〜0x00004C、0x0000B0 | ハートビート、握手、ホストの引数、起動の進み具合 |
| 0x0000C0、0x0000C4 | このファームウェアの印（`DTH3`）と版 |
| 0x001000〜0x060FFF | ホストに渡すプール（コマンドのスロットなど） |
| 0x061000〜0x0623FF | メッセージの本体（8 個） |
| 0x062800〜0x0628FF | DMA の記述子 |
| 0x064000〜0x065FFF | 使わないチャネルの書き込み先 |
| 0x068000〜0x06FFFF | CAS オブジェクトの報告ブロックの組み立て場所 |
| 0x100000〜 | イメージ、`.bss`、スタック |
| 0x800000〜0x9D5FFF | 全 PID のチャネルのリング（Raw ストリーム、Program ストリームの ES 以外） |
| 0xC00000〜0xDD5FFF | Program ストリームの ES のチャネルのリング |

### 純正のファームウェアと違うところ

- 知らないコマンドでは止まらず、結果 2 を返す。
- flush（コマンド 10）は何も送らない（純正は端数を送ってメッセージ 0x0C を出す）。close の後、ホストはエンドポイントの残りを捨てればよい。
- Raw を開いた直後の 1 チャンク（256 パケット）は捨てる。チャネルが前回の残りを先に出すため。
- ホストが読まずにリングがあふれたら、いま書いているチャンクの先頭から送り直す（送るデータは常にパケットの境界から始まる）。
- ウォッチドッグは使わない。
- カードの抜き差しは 50 ms ごとに見て（2 回続けて同じなら確定）、変化をすぐ報告する（純正は約 1 秒ごと）。活性化の報告はリセット要求から約 40 ms 後、INIT の完了はその約 150 ms 後。
- ATR は構造をたどって終わりを知る（純正は 201 ms の無受信で終わりとみなす）。
- Program は、ES のチャネルのリングと全 PID のチャネルのリングを、パケット単位で交互にエンドポイントへ送る（純正は 1 本のリングへ写してから送る）。
  中身は純正と同じで、パケットの並びの細かい順序だけが違う。
- ES は最初の鍵が来るまでスクランブルのまま出る（純正と同じ）。カードがリセットされるか抜かれると復号を止め、次の ECM からやり直す。
- 鍵を取りに行く ECM PID は 1 つ（ES に付いてきた最初のもの）。ECM の本体が 54 バイトを超えるものは扱わない（純正は 47 バイトまで）。
- 純正の再暗号化モード（Program のモード 16）は断る（結果 2）。
- close は、進行中の転送が終わるのを最大 100 ms 待ってから完了を返す。
- T=1 は応答の LRC を確かめ、誤りや無応答では 2 回まで送り直す。カードからの待ち時間延長の要求（WTX）に応える。分割された応答（チェイニング）には対応しない。
